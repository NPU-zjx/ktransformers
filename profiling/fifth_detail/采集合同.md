## 指标清单（每项必须有证据或明确失败，禁止静默缺项）

## 时间和内存解释规则

1. 全部容量保留原始 bytes，图表用 GiB。每条记录必须关联 run、round、phase、rank、PID、GPU UUID、UTC/单调时钟。
2. 同时刻账本：物理进程显存 → PyTorch reserved → allocated → 去重张量。`reserved-allocated` 是缓存/不可复用碎片的待细分总额，不能全部称浪费；`NVML-reserved` 不能全部称 NCCL。
3. 激活和临时张量从分配生命周期/调用栈认定；快照里的类别之和与 allocated 比对，保留未分类分配。原生 CUDA 分配用独立短 NSys 诊断追踪，不能用别次运行替代本次精确峰值。
4. CPU tensor storage 容量不等于 PSS/容器 anon；各进程相同虚拟地址不表示共享，跨进程共享需 inode/映射证据。
5. 1 秒采样可能遗漏瞬时峰值，补阶段边界和 PyTorch 内部峰值。cgroup memory.peak 是容器生命周期峰值，已有容器无法直接当本次峰值。必要时建立独立容器，权限和挂载复核后再启动。
6. 嵌套阶段给 inclusive/self 或非重叠分段；GPU event 包含 stream 等待，与 kernel active 时间分列。CPU/GPU 重叠时间不相加。

## 执行与交付

1. 静态门：记录真实 source/config、采集接口兼容性、磁盘预算、8 卡空闲。旧 `ktrl_online_external` 有固定 32 请求/8192 输出/旧 environment 接口等假设，禁止直接照搬启动。
2. CPU 门：监控器实采、storage 别名去重、未知项保留、时间并集/TPS分母、SSE chunk 解析、覆盖失败检查。
3. GPU 短门：全部 rank、真实生成 token、Graph 回放、Actor 更新及所有内存边界有效非空；完整指标覆盖之后才能开轻量正式两轮测量。
4. 轻量正式两轮：同一次 rollout 采 TPS/TTFT/TPOT，不用独立补跑伪装；首轮和常驻轮分别交付。
5. 重型诊断：独立有界 PyTorch memory history/trace 与 NSys；真实上下文长度，缩短窗口，明确 profiler 开销，不覆盖轻量性能结果。
6. 输出配置/源码清单、metrics 原始数据、逐阶段表、逐卡/逐进程显存账本、容器 CPU 训练/导出账本、函数/算子时间表、coverage.json 和最终报告。确实不能归因的 GiB 必须显式保留，不能编造“无缺项”。
